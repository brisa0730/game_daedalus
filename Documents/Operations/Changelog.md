## v0.05 — plain Unity behavior (2026-10-21) · **docs only, no code**

- **Landed.** The operator confirmed enemy types as plain Unity prefabs (students should learn prefabs and overrides) and dropped the planned "keep Play-mode edits" tool: Play mode throws edits away as everywhere in Unity, and students learn that. Tuning results are kept with Copy / Paste Component Values.

## v0.04 — component model (2026-10-21) · **docs only, no code**

- **Landed.** The operator set the audience and learning goals: adults in their early 20s who barely know Unity learn to place objects, add components through the Inspector and tweak settings, on a tool simpler than Corgi Engine / Flare with only basic platformer features. Students now build objects with Add Component: one Daedalus component per kind of object plus a few add-ons, at most ~8 visible settings each (the Player per collapsible section), mode-specific settings hidden. Enemy types become Unity prefabs (presets dropped); Play-mode edits to Daedalus components are kept (live tuning without settings assets).
- **GDD deltas.** GDD v0.03 → v0.04: [GDD.md](../GDD/GDD.md) (pitch: audience, learning goals, why; pillar 7 "Few settings, good defaults"; core loop), [systems.md](../GDD/systems.md) (Enemies, Editor Tools), [entities.md](../GDD/entities.md) (enemy settings, placeable elements, authored data), [architecture.md](../GDD/architecture.md), [platforms.md](../GDD/platforms.md), [Glossary.md](../GDD/Glossary.md); [Roadmap.md](Roadmap.md) §1; CLAUDE.md Architecture rules 1, 4, 8 and conventions; `decisions.md`. Commit: `v0.04: component model — Add Component workflow, ≤8 settings per component, enemy prefabs`.

## v0.03 — Unity platform (2026-10-21) · **docs only, no code**

- **Landed.** The operator moved the project from a browser tool to a **Unity 6 package** that students use inside the Unity Editor, code-free: package `com.orcapafea.daedalus`, installed from OpenUPM, minimum Unity 6000.0, developed on 6000.6.7f1 and tested on 6000.0.85f1 too. The custom pure sim carries over (its own assembly, no engine references, no Unity 2D physics for gameplay); Unity's Tilemap, sprites, URP 2D, Input System and editor replace the Canvas 2D renderer and the React editor. The browser scaffold (its plan and code) was removed from git history at the operator's request, so this v0.03 follows v0.02 directly.
- **Design.** Unity's own tools now cover painting, navigation, placement, undo and saving; `editor-core` becomes the smaller `editor-tools` (play-from-here, inspectors, presets, validation, scene autosave). The JSON project format and its migrations give way to authored data (a scene + ScriptableObject assets) that every package update must keep loading. Live tuning uses a settings asset so Play-mode changes persist. The dual-grid auto-tile layout is reopened as an Open decision, since Unity has no dual-grid tilemap; hosting is now for WebGL builds. The minimap is dropped.
- **GDD deltas.** GDD v0.02 → v0.03: [GDD.md](../GDD/GDD.md) (header, pitch, pillar 6 "Unity's tools first", core loop, open questions), [architecture.md](../GDD/architecture.md) (assemblies, time model, data flow, technology), [platforms.md](../GDD/platforms.md) (rewritten: Unity versions, distribution, storage), [systems.md](../GDD/systems.md) (Editor Tools, Tile System, Asset Import, Share), [entities.md](../GDD/entities.md) (terrains, authored data), [content.md](../GDD/content.md), [conventions.md](../GDD/conventions.md), [Glossary.md](../GDD/Glossary.md); [Roadmap.md](Roadmap.md) (§1 milestones, §2 gates, §3, §4 auto-tile layouts + hosting); CLAUDE.md (stack, architecture, conventions, testing, project config); `decisions.md`; the audit skill's clusters; `.nvmrc` removed. Commit: `v0.03: Unity platform — Unity 6 package, code-free students in the Unity Editor, OpenUPM`.

## v0.02 — first decisions (2026-10-13) · **docs only, no code**

- **Landed.** The operator settled the open decisions except hosting: a custom runtime with a Canvas 2D renderer (no game engine), a React editor, 16 px tiles, the auto-targeting attack only, wall climb only on climbable tiles, collision only from the collision layer, spikes as hazard tiles (no longer a placed element), all three auto-tile layouts with dual-grid + single built first, fixed default sound effects, a CC0 art pack to start, no student accounts in v1. Schedule: the runtime accepts a start position + ability set from `movement-prototype`, live movement sliders on the test map, a student check halfway through `editor-core`; the one-day engine spike shrinks to a render check inside the scaffold.
- **GDD deltas.** GDD v0.01 → v0.02: [GDD.md](../GDD/GDD.md) (header, Open Questions), [architecture.md](../GDD/architecture.md) (§ Technology), [systems.md](../GDD/systems.md) (Player, World, Tile System, Editor), [entities.md](../GDD/entities.md) (spikes, terrain kind), [platforms.md](../GDD/platforms.md), [content.md](../GDD/content.md), [Glossary.md](../GDD/Glossary.md); [Roadmap.md](Roadmap.md) §1 and §4 (only hosting left open); CLAUDE.md § Project Config. Commit: `v0.02: first decisions — custom Canvas 2D runtime, React editor, 16 px tiles, tile-system rules`.
